Version: 1.0

Status: Living Document

Last Updated: 2026-07-23

# Purpose

This document defines every official application error.

Every API must return only errors defined here.

No controller, service or module may invent new error codes.

---

# Error Response Format

Every API error response must follow this structure.

```json
{
  "success": false,
  "error": {
    "code": "SHIPMENT_004",
    "message": "Carrier already assigned.",
    "details": null,
    "correlationId": "01K1W9..."
  }
}
```

---

# Rules

Every error has:

- Error Code
- HTTP Status
- User Message
- Technical Description
- Suggested Resolution

# Logging Rules

Every error must log:

- Timestamp
- Correlation ID
- User ID
- Module
- Endpoint
- HTTP Method
- Request ID
- IP Address
- Stack Trace (Production Hidden)

---

# Security Rules

Never expose:

- SQL errors
- Stack traces
- Firebase errors
- Prisma errors
- Environment variables
- Internal file paths

---

# Localization

Every error supports:

- Arabic
- English

The API returns only the error code.

Frontend translates the message.

# AI Agent Rules

Never hardcode messages.

Always return an official error code.

If an error is missing:

Stop.

Update this document first.

Then implement.

---

# Definition of Done

An error is valid only if:

✓ It has an official code.

✓ It has an HTTP status.

✓ It has documentation.

✓ It is reusable.

✓ It does not duplicate another error.
