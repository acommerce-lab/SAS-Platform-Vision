## ملخص التحديث (v0.4)
- **تغيير جوهري:** `vehicle_type` أُزيل من `Carrier` بالكامل. أُضيف كيان جديد `Vehicle` (مركبة) بعلاقة 1-إلى-N مع `Carrier` — كل مركبة تحمل `vehicle_type` و`vehicle_category` مستقلين.
- `Shipment.required_vehicle_type` أصبح مصحوبًا بـ `required_vehicle_category`.
- تأكيد نهائي: `ShipperCustomer` بلا حقول حساب دخول (كان الوضع بالفعل كذلك — الآن مؤكَّد لا افتراض).
- تأكيد نهائي: `Waybill` يُصدَر تلقائيًا فور `price_approved_at` — لا حاجة لحقل "مُصدِر يدوي".
- تأكيد نهائي: انتقال `pricing_rejected → linked_to_carrier` مسموح به صراحة (إعادة ربط يدوية من Admin)، يُضاف لجدول التحويلات المسموحة.
- تأكيد نهائي: `account_status = pending_activation` يسمح بتسجيل الدخول لكن بنطاق وصول محدود جدًا (يُفرَض في Backend، لا في بنية الجدول).

## 1. نظرة عامة على الكيانات

```
Admin

Carrier (الناقل)
  │
  └── Vehicle (مركباته — عدة مركبات، كل واحدة بنوع وفئة)   [كيان جديد v0.4]
  │
  └── Shipment (الشحنات المُسندة إليه على مستوى الناقل ككل)

Shipper (الشاحن)
  │
  ├── ShipperCustomer (بيانات مرجعية فقط — لا حساب، مؤكَّد نهائيًا)
  └── Shipment

Shipment (الكيان المركزي)
  │
  ├── StatusChange
  ├── Notification
  └── Waybill (0 أو 1 — يُصدَر تلقائيًا)
```

### 2.3 Vehicle (المركبة) — ⚠️ كيان جديد v0.4

**الوصف:** مركبة واحدة يملكها/يشغّلها الناقل. الناقل يملك واحدة أو أكثر.

| الحقل | النوع | إلزامي | ملاحظات |
|---|---|:---:|---|
| `id` | UUID | ✅ | |
| `carrier_id` | UUID (FK → Carrier) | ✅ | |
| `vehicle_type` | Enum | ✅ | مثال: `flatbed`, `box_truck`, `refrigerated`, `tanker`, `other` — ⚠️ قائمة تقديرية، تحتاج تأكيد صاحب المصلحة |
| `vehicle_category` | Enum/String | ✅ | ⚠️ **قيمها الدقيقة غير محددة بعد** — قد تمثّل الحمولة (خفيفة/متوسطة/ثقيلة) أو الحجم أو تصنيفًا آخر خاصًا بشركة SAS. مصمَّم كحقل مستقل ليُحسَم لاحقًا دون تغيير بنية الجدول |
| `created_at` | Timestamp | ✅ | |

**قواعد سلامة البيانات:**
- BR-003 (BA v0.4): الناقل يُضيف مركبة واحدة على الأقل عند التسجيل (نوع وفئة إلزاميان لكل مركبة).

### 2.7 قائمة حالات الشحنة — ✅ مُحدَّثة نهائيًا (إضافة تحويل الرفض)

| القيمة | من يُشغّلها |
|---|---|
| `requested` | تلقائي |
| `linked_to_carrier` | `Admin` |
| `pending_shipper_pricing_approval` | `Admin` |
| `pricing_rejected` | `Shipper` |
| `waybill_issued` | **تلقائي بالكامل** — ✅ مؤكَّد، لا فعل إداري |
| `shipment_started` | `Carrier` |
| `in_transit` | `Carrier` |
| `delivered` | `Carrier` |
| `cancelled` | `Admin` أو `Shipper` |

**✅ تحويل مؤكَّد جديد:** `pricing_rejected → linked_to_carrier` مسموح به صراحة، ويُنفَّذه `Admin` يدويًا (نفس إجراء الربط الابتدائي، مُعاد استخدامه). لا حاجة لحالة أو Endpoint منفصل — يُعاد استخدام نفس منطق الخطوة 2 من دورة الشحنة.
