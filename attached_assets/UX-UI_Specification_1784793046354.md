## 1. مبادئ التصميم العامة

- **البساطة التشغيلية أولاً:** المنصة أداة إدارة داخلية، لا منتج تسويقي — الأولوية لسرعة إنجاز المهمة، لا للزخرفة البصرية (امتداد لمبدأ 1.8 في Product Constitution).
- **دعم RTL كامل:** الواجهة عربية أولاً (Right-to-Left)، مع بنية تسمح بإضافة الإنجليزية لاحقًا دون إعادة تصميم.
- **وضوح الحالة دائمًا:** أي شاشة تعرض شحنة يجب أن تُظهر حالتها الحالية بوضوح بصري فوري (شارة/Badge ملوّنة)، لأن دورة حياة الشحنة هي جوهر المنصة.
- **لا إجراء بلا تغذية راجعة:** كل تغيير حالة أو إجراء يُظهر تأكيدًا فوريًا (نجاح/فشل)، لا صمتًا يترك المستخدم في شك.

## 2. هيكل التنقّل حسب الدور

### 2.1 لوحة Admin
```
الرئيسية (نظرة عامة: عدد الطلبات لكل حالة)
├── الناقلون (قائمة + تفعيل/تعطيل)
├── الشاحنون (قائمة + تفعيل/تعطيل + عملاؤهم)
├── الطلبات/الشحنات (قائمة مفلترة بالحالة، تفاصيل كل طلب)
├── تذاكر الدعم
└── الإعدادات (حساب Admin)
```

### 2.2 لوحة Carrier
```
الرئيسية (شحناتي الحالية، مفلترة بالحالة)
├── تفاصيل شحنة (تحديث الحالة: بدء/في الطريق/تسليم)
├── الدردشات
└── تذاكر الدعم
```

### 2.3 لوحة Shipper
```
الرئيسية (طلباتي، مفلترة بالحالة)
├── تقديم طلب جديد
├── تفاصيل طلب (متابعة الحالة، موافقة/رفض التسعير عند الحاجة)
├── عملائي
├── الدردشات
└── تذاكر الدعم
```

## 3. الشاشات الرئيسية (Wireframe نصي)

### 3.1 شاشة تسجيل ذاتي (F-001)
```
┌─────────────────────────────┐
│   [شعار SAS]                │
│   هل أنت: ( ) ناقل  ( ) شاحن │
│   ─────────────────────────  │
│   الاسم:        [_______]   │
│   البريد:        [_______]   │
│   كلمة المرور:   [_______]   │
│   الهاتف:        [_______]   │
│   [نوعية المركبة ▾]  ← يظهر فقط إن اختار "ناقل"│
│                              │
│         [ تسجيل ]            │
└─────────────────────────────┘
```

### 3.2 شاشة تفاصيل الشحنة (النواة المركزية للواجهة)
```
┌───────────────────────────────────────────┐
│ الشحنة #SAS-2026-000123     [الحالة: 🟡 بانتظار موافقة التسعير] │
│ ───────────────────────────────────────── │
│ من: الرياض – حي العليا                     │
│ إلى: جدة – حي الروضة                       │
│ نوعية المركبة: سطحة                        │
│ الشاحن: شركة الأمل التجارية                │
│ الناقل: شركة النقل السريع                  │
│ السعر المُقترَح: 1,200 ر.س                  │
│ ───────────────────────────────────────── │
│ [أزرار الإجراء — تختلف حسب الدور والحالة]   │
│   Shipper يرى: [موافقة] [رفض]              │
│ ───────────────────────────────────────── │
│ سجل الحالة:                                 │
│   ✓ تم تقديم الطلب — 20/07/2026            │
│   ✓ رُبط بناقل — 21/07/2026                │
│   ● بانتظار موافقة التسعير — الآن           │
│ ───────────────────────────────────────── │
│ [فتح دردشة]  [فتح تذكرة دعم]                │
└───────────────────────────────────────────┘
```

**قاعدة تصميم مهمة:** الأزرار المعروضة في منطقة "الإجراء" **تُبنى ديناميكيًا** من نفس وحدة التحقق المركزية للسير (ADR-007) — لا تُكتب كشروط `if` منفصلة في كود الواجهة، لضمان اتساق الصلاحيات بين الواجهة والـ API.

### 3.3 شاشة تقديم طلب شحن (F-005)
```
┌─────────────────────────────┐
│ طلب شحن جديد                 │
│ نقطة الاستلام:   [_______]   │
│ نقطة التسليم:    [_______]   │
│ وصف البضاعة:     [_______]   │
│ نوعية المركبة:   [▾ اختر]    │
│ عميل مستفيد:     [▾ اختياري] │
│                              │
│         [ تقديم الطلب ]      │
└─────────────────────────────┘
```

### 3.4 شاشة لوحة Admin — قائمة الحسابات الجديدة
```
┌───────────────────────────────────────────┐
│ حسابات بانتظار التفعيل (3)                  │
│ ───────────────────────────────────────── │
│ شركة الفا للنقل | ناقل | سطحة | [تفعيل][رفض]│
│ مؤسسة بيتا      | شاحن |        | [تفعيل][رفض]│
└───────────────────────────────────────────┘
```

## 4. نظام الحالة البصري (Status Badges)

| الحالة | اللون المقترح | الأيقونة |
|---|---|---|
| `requested` | رمادي | ⏳ |
| `linked_to_carrier` | أزرق | 🔗 |
| `pending_shipper_pricing_approval` | أصفر | 🟡 |
| `pricing_rejected` | برتقالي | ⚠️ |
| `waybill_issued` | أخضر فاتح | 📄 |
| `shipment_started` | أزرق داكن | 🚚 |
| `in_transit` | بنفسجي | 🛣️ |
| `delivered` | أخضر | ✅ |
| `cancelled` | أحمر | ❌ |

> ⚠️ نظام الألوان مقترح مبدئي، يخضع لهوية SAS البصرية إن وُجدت (Brand Guidelines) — يحتاج مراجعة تصميمية لاحقة.

---

## 5. اعتبارات إمكانية الوصول (Accessibility)

- تباين ألوان كافٍ بين شارات الحالة والخلفية (WCAG AA كحد أدنى).
- كل زر إجراء يحمل نصًا واضحًا (لا أيقونة وحدها) لتفادي الغموض، خاصة لمستخدمين غير تقنيين (ناقلين/شاحنين قد لا يكونون معتادين على واجهات معقدة).
